CLAIM UNDER TEST (as given):
  The nav's .cw-nav.is-scrolled rule and four inline link/figure classes
  (.cw-mlink, .cw-section-cta, .cw-offer__packages-link, .cw-exits__co,
  .cw-exits__val) inherit --cw-fg/--cw-bg from the root's 0.7s
  cubic-bezier(0.16,1,0.3,1) world-crossfade, but each declares its own
  separate, shorter (or absent) transition on the same property. While the
  root transition is in flight, the inherited value keeps changing every
  frame, so each element's own transition is repeatedly cancelled and
  restarted. One live instrument (transition-attrib.mjs, this folder, n=1)
  measured 868 transition lifecycle events for 2 real colour writes (132
  transitionrun / 126 transitioncancel on .cw-mlink alone across 4 DOM
  instances). Predicted fix: syncing every descendant's transition
  duration/curve to the root's exact 0.7s cubic-bezier(0.16,1,0.3,1) should
  collapse the churn toward ~2 events (one clean run per real write, zero
  cancels).

*** TEST ARTIFACT FOUND (mechanism-before-retry check, run before trusting
the as-given result): ***
This declaration is invalid CSS. A `transition` shorthand value list may
carry exactly ONE trailing `!important` for the whole declaration; putting
`!important` after EACH comma-separated item (as the task's literal text
does) is not valid value grammar. Verified directly against the live page,
not assumed:
  - verify-inject.mjs: computed transitionDuration on .cw-mlink,
    .cw-section-cta, .cw-nav(.is-scrolled), .cw-exits__co is IDENTICAL
    before and after page.addStyleTag(exp-T2.css) in every case (e.g.
    .cw-mlink stays "0.2s, 0.2s" / "color, border-color"; nav.is-scrolled
    stays "0.25s, 0.25s" / "background, color" -- none show 0.7s).
  - verify-inject2.mjs: the <style> tag DID land in the DOM (1 rule, full
    text present, sheet.cssRules.length === 1, no console errors, no CSP
    block) -- so the stylesheet itself loaded fine.
  - verify-inject3.mjs: enumerating cssRules directly shows why --
    rule.style.getPropertyValue("transition") is EMPTY on the injected rule
    (rule.selectorText is intact, but the `transition` declaration itself
    was dropped by the parser as invalid), while el.matches(the injected
    selector) is true. The rule exists and matches the elements; its one
    declaration just never parsed.
Running exp-T2.css as literally given therefore tests nothing -- it is a
no-op neutralizer, not a disproof of the claim. Per "mechanism before retry,
never retry verbatim": a syntax-corrected version of the SAME selector list
and SAME intent (one trailing !important covering both comma items) was
written to exp-T2-fixed.css and independently verified to actually apply
(verify-inject4.mjs: .cw-mlink, .cw-section-cta, .cw-nav.is-scrolled, and
.cw-exits__co all show transitionProperty "background, color" / duration
"0.7s, 0.7s" after injection -- the intended change is now live in the
computed styles). Both the as-given and the syntax-corrected variant were
run and are reported below, so the as-given (no-op) result is not the basis
for the verdict on its own.

VERDICT: not_causal.
The neutralizer as literally given in the task text is invalid CSS and
never applied to a single computed style on the live page (independently
verified three ways: before/after computed-style diff, DOM/CSSOM inspection
of the injected rule showing its `transition` declaration was dropped by
the parser, and cross-check that the selector itself does match the target
elements) -- so its own A/B result (0-1.5% movement, i.e. none beyond noise)
cannot be read as either confirming or refuting the claim on its own.
Substituting a syntax-corrected version of the identical selector list and
identical intent -- independently confirmed to actually change the computed
transition-duration/property on all six listed elements to 0.7s
background+color, matching the root crossfade exactly as the claim
prescribes -- produced only a small (0-16%), direction-consistent but
magnitude-inconsistent effect (2 of 3 runs showed zero change in the
cancel-specific sub-metrics that most directly test "cancel-restart churn"),
far short of the claim's own predicted near-total collapse (toward ~2
events / ~0 cancels) on any of the 3 runs. Per the task's own verdict rule
("'not_causal' if it does not move [in the predicted direction beyond
noise]"), the predicted collapse did not occur on any run, so the
transition-duration-mismatch mechanism, taken alone, is not the primary
driver of the measured transitionrun/transitioncancel churn. The small,
inconsistent partial effect seen in the corrected variant suggests
duration-matching is at most a minor contributing factor; the dominant
cause of the ~200+ cancel events on .cw-mlink and the other listed elements
remains unexplained by this claim and needs a separate root-cause pass (for
example: how many times WorldSwitcher's IntersectionObserver callback
actually re-writes --cw-fg/--cw-bg per scroll pass, and whether descendants
each re-resolve `color: var(--cw-fg)` independently on every one of those
writes regardless of their own transition's duration) -- out of scope for
this evidence-only phase, which is limited to the one A/B experiment (T2) as
specified.
